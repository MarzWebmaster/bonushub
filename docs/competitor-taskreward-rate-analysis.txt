============================================================
HOW TASKREWARD SETS RATES
============================================================

MODEL: Vendor-Set Pricing with Platform Commission

1. VENDOR creates a 'service package' in marketplace
   - Sets: title, description, price per unit
   - Sets: tasks_per_unit (e.g. 40 likes per package)
   - System auto-calculates: reward_per_task = (price × commission_rate) / tasks_per_unit
   - Or vendor manually sets reward_per_task

2. TASKREWARD takes commission from vendor payment
   - Worker earning = reward_per_task × tasks_per_unit
   - Platform keeps = vendor_price - worker_earning

3. WORKER sees rate per task on task board
   - Picks up task → completes → uploads proof
   - Vendor reviews manually → approves → worker gets reward

============================================================
IMPLICATIONS FOR BONUSHUB
============================================================

1. RATE MODEL: Vendor-sets-price, platform takes commission
   → BonusHub should follow similar model
   → Commission: 30-40% (lower than TaskReward's 68% to attract vendors)

2. FLAT RATES: RM0.03 dominates (58% of services)
   → Simple flat rate model works
   → BonusHub can set default rate tiers: RM0.03, RM0.05, RM0.10, RM0.20

3. HOURLY: RM1.80-3.00/hour average
   → Below Malaysian minimum wage (RM1,500/month ≈ RM8.65/hour)
   → Workers supplement income, not primary income

4. COMMISSION GAP: TaskReward takes 68% — very high!
   → BonusHub can differentiate: 30-40% commission
   → Vendors get better value, workers get higher rewards

5. DRIP FEED: 61% of services use it
   → Critical feature for vendor control
   → Prevents task flooding, paces engagement naturally

6. VENDOR REVIEW: 100% manual review required
   → Trust bottleneck — vendor must approve every submission
   → BonusHub can add optional auto-approve for low-risk tasks
